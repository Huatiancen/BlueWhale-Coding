# BlueWhale 无固定上限 Agent Loop 设计

## 目标

BlueWhale 默认运行到模型自然给出最终回答，不再因统一的模型调用次数或总时长限制截断复杂编码任务。系统仍统计模型调用次数，并每 20 次执行一次非阻断的进度审计。

## 运行边界

- `Limits.max_steps` 和 `Limits.max_wall_time_seconds` 改为可选值，默认为 `None`。
- 默认模式下，模型调用次数和运行时长只记录、不终止任务。
- 测试、评测或特殊部署可显式传入正整数上限，原有确定性终止语义保留。
- 用户主动停止、权限拒绝、不可恢复的 API 错误、连续模型协议错误和工具安全错误仍可终止任务。

## 每 20 次进度审计

- 新增可配置的 `progress_check_interval`，默认值为 20。
- 当单次连续执行中已完成的模型调用次数达到 20 的倍数时，在下一次模型请求中附加一条系统级进度审计指令；新的追问轮次重新计数。
- 审计不单独调用模型，不暂停任务，不自动终止，也不向用户展示模型的内部思考。
- 审计指令要求模型：
  1. 检查已完成工作、未解决错误和剩余目标；
  2. 避免重复已失败的读取、命令或修改路径；
  3. 如果修改和验证已完成，立即停止调用工具并返回最终答案；
  4. 否则选择下一个信息增益最高的操作。

## 上下文与持久化

- 继续使用现有 `ContextManager` 按字符预算压缩旧消息和工具输出，保持工具调用协议完整。
- 每次模型响应、工具结果、检查点和最终回答继续写入本地轨迹和检查点。
- 取消固定上限不改变历史恢复、中断恢复和用户停止的语义。

## 错误处理

- 进度审计只是下一轮上下文的附加指令，不得将任务标记为失败或已停止。
- 若显式配置了步数或时长限制，达到限制后仍使用已有的无工具收尾调用生成最终说明。
- 对没有显式限制的默认任务，只有用户或明确的不可恢复错误可终止循环。

## 测试要求

- 默认 `Limits` 超过 20 次模型调用后仍能继续并自然完成。
- 第 21 次请求收到进度审计指令，第 22–40 次不重复注入，第 41 次再次注入。
- 进度审计不改变步数统计，不触发额外 API 调用。
- 显式 `max_steps=1` 与 `max_wall_time_seconds=1` 仍按原语义终止。
- 中文输入、历史恢复、工具调用和最终回答分类的现有回归测试保持通过。
